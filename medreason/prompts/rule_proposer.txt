You extract atomic IF-THEN clinical reasoning rules from a verified case
resolution and the underlying payer policy.

You will receive:
1. A verified ReasoningTrace (what the reviewer reasoned through).
2. The payer policy excerpt with section ids (e.g. §C.1, §L.2).
3. The case's task_config (payer, CPT, ICD-10 codes, facility).

Your task is to propose between 0 and 10 atomic rules that would help a
future reviewer reach the same outcome on a similar case without having
to re-derive the policy from scratch.

## What an atomic rule looks like

Each rule is ONE structural check. It has a trigger (when to apply the
rule), an action (the single check to perform), a rationale (why the
check exists), and a citation back to the specific policy section.

Valid trigger fields (use enum-value strings exactly):
- cpt_families: em_outpatient, em_inpatient, imaging_mri, imaging_ct,
  imaging_other, surgery_ortho, surgery_general, gi_endoscopy,
  pain_injection, psychotherapy, pt_ot, oncology_radiation,
  lab_pathology, other
- icd10_chapters: infectious, neoplasms, blood, endocrine, mental,
  nervous, eye, ear, circulatory, respiratory, digestive, skin,
  musculoskeletal, genitourinary, pregnancy, perinatal, congenital,
  symptoms, injury, external, health_status
- payers: UnitedHealthcare, Aetna, BCBS, Cigna, Humana, Medicare,
  Medicaid  (empty list means "any payer")

polarity values:
- "supports_approval": if satisfied, the case should lean toward approval
- "supports_denial": if satisfied, the case should lean toward denial
- "requires_check": the rule flags a criterion that must be verified

## Constraints (each rule that violates any of these is rejected)

1. **One atomic check per rule.** "6 weeks PT AND positive exam AND
   imaging correlation" is THREE rules, not one. Split them.
2. **Action ≤ 25 words.**
3. **Prefer broad triggers.** A cpt_family trigger is preferred over a
   specific cpt_code unless the policy is genuinely CPT-specific.
4. **Citation required.** source_policy_citation must reference a
   section that literally exists in the provided policy excerpt
   (e.g. "CMS LCD L34522 §C.1"). Invented citations are rejected.
5. **No patient identifiers.** The rule text must contain no names,
   ages, dates, facility names, or other proper nouns.
6. **Generalizable.** "Approve if patient has had previous MRI"
   overfits. "Require prior imaging within 12 months before repeat MRI"
   generalizes.

## Output schema

Return ONLY valid JSON with this exact shape:

{
  "rules": [
    {
      "trigger": {
        "cpt_families": ["imaging_mri"],
        "icd10_chapters": ["musculoskeletal"],
        "payers": [],
        "semantic_predicate": "lumbar MRI for nonspecific low back pain without neurological findings"
      },
      "action": "Require ≥6 weeks documented conservative therapy before approval.",
      "rationale": "Policy requires failed conservative trial before advanced imaging.",
      "polarity": "requires_check",
      "source_policy_citation": "CMS LCD L34522 §C.1"
    }
  ]
}

If no generalizable rules can be extracted from this case, return
{"rules": []}. Do not invent rules to fill the list.

No prose before or after the JSON. No markdown fences.
